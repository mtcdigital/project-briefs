The /summarize Skill

A one-word command that turns a whole Claude Code project into a plain-English page you can text to somebody.

Working Updated Sep 1, 2026 5 min read

⚡ The 10-second version

  1. Everett types /summarize in any Claude Code chat, and it turns everything that chat knows about the project into one plain-English web page.
  2. It gives back one link he can text you. No app, no login, works on your phone.
  3. Run it again later and the link stays the same — it just updates, and the old version is saved so you can see what changed.

🧭 What this actually is

Everett works on projects with Claude Code (an AI that lives in his terminal). That AI ends up knowing everything — every decision, every dead end, every half-finished piece. The people he collaborates with know almost none of it.

Catching everyone up by text takes forever and always leaves stuff out. This closes that gap in about 30 seconds.

💡 What I learned building it

  • Private didn't work. Everett's project folders on GitHub are private. Private pages require the reader to log in with a GitHub account — which defeats the whole point. So these pages sit in one public folder instead.
  • "Public" doesn't mean "findable." Every project folder gets a random tag on the end of its web address, like meme-coin-trader-k7f2q9. Plus every page tells Google to stay out. It works like an unlisted YouTube video — you can't stumble onto it, but anyone you send it to can open it instantly.
  • A frozen old page still needs working navigation. First attempt: old versions couldn't see the newer ones, so you'd hit a dead end. Fixed — the words on an old page never change, but its list of "other versions" always stays current.
  • The hard part isn't the code, it's the writing rules. Most of the work went into telling the AI how to write: define every piece of jargon, use real numbers instead of "some" and "several", and say plainly what's broken instead of what's hoped for.
One real limit: anyone holding the link can read the page. So no passwords, keys, or client details ever go on one. It says "the key is in the .env file" — never the key itself.

🔀 The fork in the road

The system works. The open question is how people find out a page has been updated. Right now: nothing tells them.

Option A — Just text the link again

Leaning this way for now

  • Zero extra building
  • The link never changes, so re-sending is easy
  • A text is honestly the fastest nudge anyway
  • Easy to forget on a project with 4+ people

Option B — Auto-email the group

Build it only if A gets annoying

  • Nobody misses an update
  • Everyone sees the same thing at the same time
  • Needs a saved contact list per project
  • Might turn into noise people ignore
Recommendation: run with Option A for a few real projects first. If Everett finds himself re-texting the same group over and over, that's the signal to build Option B.

📖 Words you might not know

Claude Code
An AI assistant that runs inside a terminal window and can actually read and change files on the computer, instead of just chatting.
Skill
A saved instruction sheet for that AI. Typing /summarize loads the sheet and it follows the steps. Like a recipe card the AI reads before cooking.
Repo (repository)
A folder that lives on the internet and remembers every change ever made to it. This whole system lives in one.
GitHub Pages
A free service that turns a folder of files into a real, public website. That's how this page reaches your phone.
Unlisted
Not password-protected, but not findable either. Hidden from Google, and the web address has random characters so it can't be guessed.
.env file
A private file on Everett's computer where passwords and keys are kept. It never gets uploaded anywhere.
